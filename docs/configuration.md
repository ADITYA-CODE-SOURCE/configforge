# Configuration

ConfigForge configuration starts with `version: v1`. The project implements strict YAML loading, built-in defaults, typed environment overrides, and validation for features, route policies, privacy redaction, and logging.

Unknown YAML fields are rejected. Validation errors include field paths and YAML positions when available.

## Generated Artifacts

ConfigForge can generate artifacts from manifests:

- **JSON Schema** (`schemas/config.schema.json`) — Draft 2020-12, with `additionalProperties: false`, enums, defaults, numeric limits, and descriptions.
- **Go defaults** (`pkg/config/generated.go`) — `EnvMetadata` and `ManifestDefaults` with the `// Code generated by ConfigForge. DO NOT EDIT.` header.
- **Markdown docs** (`docs/configuration_options.md`) — option tables for each manifest.

Run:

```bash
configforge generate --manifests ./manifests --output .
configforge schema --output schemas/config.schema.json
configforge explain features.new_checkout --config examples/configs/default.yaml
```

Generation is deterministic: running it twice without input changes produces no diff.

## Configuration Precedence

```text
built-in defaults → environment variables → YAML configuration
```

## Manifests

Manifests live under `manifests/` and declare each component's options once, including type, default, limits, environment-variable mapping, and description. See `docs/configuration_options.md` for the generated option reference.
